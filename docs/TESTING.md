# Akev acceptance test plan

Automated tests live in each crate (`cargo test`) and in `crates/akev-api/tests/e2e.rs`. This
document lists the end-to-end scenarios a release must pass (automated where possible, with
real clients: curl, reqwest, Chrome headless).

## Capture fidelity
1. HTTP proxy (absolute-form): `curl -x http://127.0.0.1:PORT http://localhost:ORIGIN/x?y=1` → exchange recorded with exact URL, method, status, headers, body, timings.
2. HTTPS via CONNECT + MITM: `curl -x … --cacert ca.pem https://localhost:TLSORIGIN/` → recorded; client TLS info (SNI, ALPN, version, cipher, JA3/JA4) present; upstream certificate summary present.
3. HTTP/2 client: `curl --http2 …` over TLS → `httpVersion: HTTP/2`; h2c prior knowledge too.
4. SOCKS5: `curl --socks5-hostname 127.0.0.1:PORT …` → recorded.
5. Header fidelity: a raw TCP client sends `X-MiXeD-Case: 1`, duplicate headers and unusual order → upstream receives them byte-identical; recorded headers identical.
6. Chunked request/response with trailers; `Expect: 100-continue`; HEAD/204/304 bodies.
7. Large bodies: 200 MB download streams without buffering (proxy RSS stays low); capture truncated at `maxBodyBytes` with `truncated: true` and full `wireSize`.
8. Content-encoding: gzip/br/zstd responses decoded in BodyView; decode errors reported.
9. WebSocket: echo server through the proxy (ws and wss) → `kind: web-socket`, messages both directions with payloads, close code.
10. SSE: `text/event-stream` response streams to the client immediately; events appear as messages live.
11. Upstream failures: connection refused, DNS failure, self-signed/expired/wrong-host cert, timeout → client gets a 502 explaining the error; exchange `error.kind` set correctly.
12. TLS passthrough host → recorded as tunnel, not decrypted; bytes counted.
13. Client rejecting the CA (curl without `--cacert`) → TLS failure row with `client-tls-rejected`.
14. Device setup page: `curl -x … http://akev.cert/` → HTML; `/ca.pem`, `/ca.crt`, `/ca.mobileconfig` downloadable.
14a. Transparent capture (Linux): `crates/akev-proxy/tests/transparent.rs` injects the original destination through `ProxyHandle::set_original_destination_lookup` and proves HTTP (Host + original port), HTTPS by SNI, HTTP/2, no-SNI TLS (original IP), TLS passthrough and raw tunnels to the original destination, direct connections, loop refusal and live settings; `crates/akev-api/tests/transparent_e2e.rs` covers `GET /api/transparent`, the redirect check, plans and the interceptor. Against the real kernel without root: `scripts/transparent/verify-netns.sh` runs a release daemon, upstreams and the generated nftables / iptables rules in a private user + network namespace (machine-wide with `SO_MARK` exclusion, iptables, per-user, per-app via `akev-capture.slice` + `socket cgroupv2`, CA env vars on the launch command, teardown).

## Rules
15. Mock (status/headers/JSON body), map remote (to another local origin, strip prefix, preserve host), map local (file & directory, traversal blocked), rewrite request & response (headers, URL, JSON merge patch, find/replace), delay (≥ requested), throttle (download rate within ±20%), close/reset/timeout, WebSocket echo/reject, highlight (row colour), script (modify + short-circuit), max matches ("once"), modifier stacking order, disabled groups.
16. Breakpoints: request pause → `paused` stream event → edit via `POST /api/breakpoints/:id/resume` → upstream receives the edit; response pause similarly; respond/close/reset options; resume-all.
17. Rule hit counters update and stream `rule-stats`.

## API, store, UI
18. `/api/exchanges?filter=` and stream `set-filter` deltas for status/host/body queries; invalid filter returns error span.
19. HAR export → import round trip (incl. binary bodies & WebSocket messages); `.akev` session round trip lossless.
20. Compose `POST /api/send` and replay → new exchanges with `via: composer`; cURL import; snippets for all targets.
21. Auth: requests without token → 401; a cookie never authenticates; foreign `Origin` → 403. Browser UI (`ui/src/api/auth.test.ts`): `/?token=` is stripped from the address bar and remembered in localStorage per daemon origin, so new tabs, reloads and bookmarks stay signed in without the token ever returning to a URL; a remembered token Akev rejects at startup (it restarted with a new one) is forgotten and the "not authorized" screen says why.
22. Settings: change proxy port → proxy rebinds live; TLS passthrough & ignore-cert lists apply without restart; settings persist across restarts; corrupt settings file → backed up & defaults.
23. Recording off → traffic proxied but not stored.
24. MCP: `initialize`, `tools/list`, `tools/call akev_list_exchanges`, `akev_add_mock` then traffic is mocked; `akev mcp` stdio bridge works against a running daemon.
24a. LLM traffic lens (`crates/akev-api/tests/llm_e2e.rs`): an OpenAI-compatible SSE stream and an Anthropic-compatible stream through the proxy → summary `llm: { provider, model }`, `is:llm` / `model:` / `provider:` filters, `GET /api/exchanges/:id/llm` reassembles text + tool calls, measures TTFT from the recorded events, `404 not-llm` for other exchanges; MCP `akev_llm_conversation`. Parser fixtures for every provider (streamed and not, malformed, truncated at every offset) in `crates/akev-content/src/llm/tests.rs`.
24b. WireGuard mode: `crates/akev-wireguard/tests/tunnel.rs` drives the server with a real WireGuard client (boringtun + smoltcp over loopback UDP): TCP echo with the original destination, 3 MiB each way, 40 concurrent connections to one destination, IPv6 SYN, connection limit → RST, reset flag and server stop, wrong key → no session, DNS relay over UDP and TCP (truncation → TCP retry), UDP relay, QUIC drop. `tests/e2e.rs` adds the proxy: HTTP (keep-alive, no `Host`), HTTPS MITM trusting only the Akev CA, server-speaks-first tunnel, `akev.cert` + CA download through the tunnel. `crates/akev-api/tests/wireguard.rs`: enable/disable live via `/api/wireguard`, persisted keys, recorded exchanges with `via: wireguard`, `source:wireguard`, handshake status, `.conf` download, key regeneration, busy port. Manual: `cargo run --release -p akev-wireguard --example wg_smoke -- 127.0.0.1:51820 <data-dir> --https example.com --bench 32` against a running daemon.
24b. HTTP/3 (`crates/akev-proxy/tests/http3.rs` with in-process quinn + h3 peers and rcgen certificates; `crates/akev-api/tests/http3_api.rs`): upstream requests over QUIC with headers, streamed bodies, request & response trailers, connection reuse / multiplexing / a second connection past 64 streams, multi-MB bodies both ways; `Alt-Svc` discovery on an alternative port, `clear`, `ma` expiry; `prefer` mode falling back to TCP and remembering the origin; forced `http3` falling back to TCP; certificate verification (untrusted → refused over QUIC; insecure / ignore-errors → accepted); never through upstream proxies; the QUIC listener (h3 client → Akev → HTTP/1.1 or HTTP/3 origin) recording HTTP/3 exchanges with SNI/ALPN, chunked upload, relayed trailers, mock rules, untrusted clients → `TlsFailed`; listener start / move / busy-port error / rebind / stop via settings; `serve_quic_socket` with an original destination; Compose and `POST /api/send` with `httpVersion`. Manual: release daemon + `curl --http3-only` against the listener and public HTTP/3 servers (Cloudflare `cdn-cgi/trace` reports `http=http/3`).
24b. Upstream TLS fingerprints (`crates/akev-proxy/tests/impersonate.rs`, `crates/akev-api/tests/tls_profiles.rs`): local rustls / h2 servers capture Akev's raw ClientHello and HTTP/2 preface and fingerprint them with Akev's own parser. Every build: native connections report the JA3/JA4 they sent; without the backend, browser profiles fall back to native with a `note`. With `--features impersonate` (`make test-impersonate`): Chrome / Edge / Firefox / Safari hellos match the browsers' cipher, extension (order, or Chrome's per-connection permutation), group and signature-algorithm lists, GREASE placement, published JA4s and the published Firefox / Safari JA3s; `http/1.1`-only hellos (WebSockets) drop ALPS like Chrome; HTTP/2 SETTINGS order/values, WINDOW_UPDATE, HEADERS priority and pseudo-header order match per browser; certificate errors / alerts / EOF map to the native codes; client certificates are presented; stalled streams can't starve a browser-sized connection window; per-host overrides, rule overrides and `mirror-client` work end to end through the proxy. **CI**: run the suite twice — default (pure Rust) and `cargo test --features akev-cli/impersonate,akev-api/impersonate,akev-proxy/impersonate` on a runner with cmake, a C/C++ compiler and libclang (`apt-get install cmake clang libclang-dev`; on macOS Xcode + `brew install cmake`; on Windows the VS build tools + LLVM + NASM).
24b. JVM attach (`crates/akev-api/tests/jvm_attach.rs`, needs a JDK ≥ 11, skipped otherwise): a Java app serving and calling HTTPS (HttpURLConnection, a per-request and a startup `java.net.http.HttpClient`) runs direct; `POST /api/interceptors/jvm/activate {pid}` → its requests go through the proxy, decrypted and recorded, loopback stays direct, an untrusted server stays rejected; `deactivate` → direct again. The agent's own Java self-test (with and without JSSE access, `-javaagent:` startup, `Attach` CLI against a live JVM) is `crates/akev-intercept/tests/java_agent.rs`.
25. CLI: `akev capture --output x.har --duration 5` writes valid HAR; `akev status`, `akev ca path`, `akev stop`.
26. UI: loads with token, stream connects, traffic list shows live exchanges, detail pane renders every tab, rules editor round-trips, compose sends, connect lists interceptors, settings save. Visual review via headless Chrome screenshots in dark & light themes.

## Performance
27. `akev-loadgen --proxy … --requests 100000 --concurrency 64`: ≥ 5k req/s on a laptop, 0 failures; daemon RSS < 400 MB after 100k small exchanges; UI scroll stays smooth with 100k rows. Another 200k requests: the store stays at 200,000 exchanges (`stats.evicted` counts the rest) and RSS levels off. Store-only benchmarks: `cargo test -p akev-store --release --test scale -- --ignored --nocapture --test-threads=1` (method and results in `docs/PERFORMANCE.md`).
